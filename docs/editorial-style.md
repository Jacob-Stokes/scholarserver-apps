# Application interface voice

Use the same professional, direct and quietly helpful voice as ScholarServer's
Manager. Paperless-ngx is a useful touchstone: state what the reader needs, what
to do and what happens next. Assume the researcher is capable.

- Describe concrete actions. Prefer “Convert existing PDFs” to “Backfill” and
  “Check attachment access” to “Resolve an attachment”.
- Remove repeated encouragement, vague reassurance and internal implementation
  terms that do not help the user act.
- Preserve prerequisites, permissions, costs, licensing notices, data-loss
  warnings and recovery steps. State which device or website to use.
- Describe the scope of a check rather than saying “Protected”, “Verified” or
  “Safe” without qualification. Do not promise safe retries for uncertain writes.
- Use Manager's labels: **Applications**, **Installed**, **Catalog**,
  **Configuration**, **Files & storage**, **Access**, **AI connections** and
  **MCP server URL**. Introduce upstream terms such as graph or vault when needed.
- Keep user instructions separate from development history and test records.
  Link to contributor documents rather than mixing them into setup steps.
- Keep app-specific wording here; use shared UI presentation rather than
  reimplementing screens. Do not edit immutable published package metadata for
  wording changes: include them in the next package release.

The platform's companion guide is `docs/editorial-style.md` in academic-system.
